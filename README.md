# STM32 温湿度采集系统

> 基于 STM32F103C8T6 的环境监测节点 —— 传感器采集 · OLED 本地显示 · 串口数据上报

**项目状态**：开发中 · 2026-10 启动

```
传感器采集 → STM32 节点 → OLED 显示 / 串口上报
```

---

## 项目简介

本项目实现一个基于 STM32F103 的温湿度监测终端。

DHT11 采集环境温湿度数据，经 STM32 处理后同时输出到 OLED 显示屏和串口，
串口数据可由上位机实时接收并绘制曲线。

**项目目标**：完整走通"硬件选型 → 原理图设计 → PCB 打样 → 焊接调试 →
固件开发 → 软硬件联调"的全流程，并沉淀为可复用的工程模板。

## 踩坑记录

> 本节是项目最有价值的部分。每解决一个问题即记录一条 —— 现象 / 原因 / 解决 / 收获。

### 1. DHT11 首次读取必然失败

- **现象**：上电后第一次读取返回失败或数值异常，第二次才正常
- **原因**：DHT11 上电后内部需要 ≥1s 完成初始化，过早读取时序不成立
- **解决**：首次读取前加入 `HAL_Delay(1500)` 等待
- **收获**：单总线协议对时序敏感，初始化等待不可省略

### 2. printf 无输出

- **现象**：程序运行正常但串口助手收不到任何数据
- **原因**：Keil 未启用 MicroLIB，且 `fputc` 未重定向
- **解决**：Options for Target → Target → 勾选 **Use MicroLIB**，并重定向 `fputc` 到 `HAL_UART_Transmit`
- **收获**：嵌入式里 `printf` 不是免费的，它最终要落到某个外设上

## 技术要点

### DHT11 单总线驱动

- **us 级精确延时**：不能用 `HAL_Delay`（最小单位仅毫秒），改用 `SysTick` 计数实现
- **校验和验证**：读取 5 字节后比对前 4 字节之和的低 8 位与第 5 字节，不匹配则判定通信失败
- **错误码分级**：区分「无应答 / 应答异常 / 校验失败」三种错误，而非静默重试
- **上电等待**：首次读取前等待 ≥1s

### 非阻塞调度

- 使用 `HAL_GetTick()` 记录时间差判断采样周期，替代 `HAL_Delay` 阻塞等待
- 原因：`HAL_Delay` 期间 CPU 处于等待状态，无法处理其他任务
- 附加收益：保留了向 RTOS 迁移的可能性
