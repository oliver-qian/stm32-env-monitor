# STM32 温湿度采集系统

**状态**：开发中 · 2026-10 启动 · 最近更新 2026-11-01

> 当前目标：完成 DHT11 单总线驱动，读取 5 字节数据并通过校验，再接入 OLED 与串口。

## 项目概览

使用 STM32F103C8T6 完成一条最小可演示链路：

```text
DHT11 ── 单总线 ──> STM32 ── I2C ──> OLED
                        └── UART ──> CH340 / 上位机
```

第一版只追求稳定跑通，不提前加入无线、RTOS 或复杂上位机。完成“采集 → 校验 → 显示 → 上报”闭环后，再扩展开关、菜单、无线模块和 PCB。

| 调试工具 | USB 逻辑分析仪 | 检查 I2C、UART 和单总线波形 |

接线重点：

- DHT11 数据线接 `PA7`。
- MCU 使用开漏输出，数据线必须有上拉；模块自带上拉时要确认，裸传感器需要外接约 `10 kΩ`。
- DHT11 前后两次读取至少间隔 `1 s`，调试时建议先用 `2 s`。
- ST-Link 必须使用 SWD 模式，不是 JTAG。

## 当前任务

### DHT11 调用关系

```text
main
  └─ DHT11_Start()       发起始信号，返回应答结果
       └─ DHT11_Check()  检查完整应答顺序
            └─ DHT11_WaitLevel()  等待指定电平
```

### 编写顺序

1. 统一头文件与源文件的函数声明。
2. 让 `DHT11_Start()` 返回 `DHT11_Check()` 的结果。
3. 实现 `DHT11_ReadByte()`：每个 bit 等待低电平结束，延时约 40 us 后采样高电平。
4. 实现 `DHT11_GetData()`：连续读取 5 字节并校验。
5. 先用串口打印原始字节，确认无误后再接 OLED。
6. 在主循环中每 2 秒读取一次，并显示成功或错误状态。

### 数据帧

| 字节 | 含义 |
|---|---|
| `raw[0]` | 湿度整数部分 |
| `raw[1]` | 湿度小数部分 |
| `raw[2]` | 温度整数部分 |
| `raw[3]` | 温度小数部分 |
| `raw[4]` | 校验和 |

```c
uint8_t sum = raw[0] + raw[1] + raw[2] + raw[3];
if (sum != raw[4]) {
    /* 数据校验失败 */
}
```

## 踩坑记录

### 1. 变量声明不能写在可执行语句之后

- 现象：ARMCC 报 `#268: declaration may not appear after executable statement in block`
- 原因：工程按 C90 规则编译，局部变量声明必须放在代码块中的可执行语句之前
- 解决：把声明提到函数开头；不要只依赖某台电脑上的 Keil 选项

### 2. ST-Link 连不上目标

- 原因：Debug 里选了 JTAG，实际只连接了 SWDIO 和 SWCLK
- 解决：Debug → Settings → Port 改为 `SW`

### 3. `Undefined symbol OLED_Init`

- 原因：`OLED.c` 在磁盘上，但没有加入 Keil 工程，因此没有 `oled.o` 提供函数定义
- 解决：把 `OLED.c` 加入目标中的 `Hardware` 组并重新编译
- 结论：头文件只负责声明；`.c` 必须参与编译和链接

### 4. 调用函数时误写 `(void)`

错误写法：

```c
return DHT11_Check(void);
```

正确写法：

```c
return DHT11_Check();
```

`void` 用于声明和定义“不接收参数”，调用函数时只写空括号。

### 5. 声明与定义返回类型不一致

`dht11.h` 和 `dht11.c` 必须保持一致：

```c
/* dht11.h */
uint8_t DHT11_Start(void);
uint8_t DHT11_Check(void);
```

如果头文件仍写 `void DHT11_Start(void);`，而源文件写 `uint8_t DHT11_Start(void)`，编译器会判定为不兼容的声明。

## 技术笔记

### GPIO：推挽与开漏

| 模式 | 高电平 | 低电平 | 常见用途 |
|---|---|---|---|
| 推挽 `Out_PP` | 主动接 VDD | 主动接 GND | LED、普通数字输出 |
| 开漏 `Out_OD` | 释放，靠外部上拉 | 主动接 GND | I2C、DHT11 等共享总线 |

多设备共享一条线时，推挽输出可能让一个设备输出高、另一个设备输出低，形成短路径。开漏模式下所有设备只能主动拉低，高电平由外部上拉提供，因此不会发生这种冲突。

### DHT11 为什么使用开漏

- `DHT11_OUT(0)`：MCU 主动拉低
- `DHT11_OUT(1)`：MCU 释放总线
- 释放后总线由约 `10 kΩ` 上拉电阻拉高
- DHT11 和 MCU 分时拉低同一条线，因此不能使用推挽输出

### 编译与链接

```text
.c + .h → 预处理 → 编译 → .o → 链接 → .axf → .hex/.bin
```

- `U`：当前目标文件需要、但自己没有定义的符号
- `T`：当前目标文件已经定义的函数或变量
- `L6218E: Undefined symbol`：有 `U`，但所有目标文件中都找不到对应的 `T`
- `L6200E: Multiply defined`：同一符号出现了多份定义

### 函数参数、返回值与调用

```c
uint8_t DHT11_Start(void)
//  ↑          ↑       ↑
// 返回类型    函数名  不接收参数
```

- 声明和定义无参数函数：写 `(void)`
- 调用无参数函数：写 `()`
- 参数从调用者进入函数
- 返回值从被调用函数回到调用者

```c
return DHT11_Check();
```

含义是：先执行 `DHT11_Check()`，再把它返回的值继续交给上一层。

### 返回值约定

本工程使用 `0 = 成功`，非 0 表示失败。错误码在头文件中说明含义，避免只看到一个无法判断原因的数字。

```c
return 0;   /* 成功 */
return 1;   /* 无应答 */
return 2;   /* 读取超时 */
return 3;   /* 校验失败 */
```

### PC13 的特殊限制

STM32F103 的 PC13、PC14、PC15 由备份域供电，驱动电流和速度受限，不适合作为电流源直接驱动 LED。蓝板板载 LED 使用灌电流接法，因此 PC13 输出低电平时点亮。
